Scope the `Dependency Review` workflow's concurrency group by PR number instead of `github.ref` — on `pull_request_target`, `github.ref` is always `refs/heads/main` for every PR, so any two PRs' Dependency Review runs shared one concurrency group and canceled each other (`cancel-in-progress: true`), silently turning a passing check into a "cancelled" failure whenever two PRs updated close together.
